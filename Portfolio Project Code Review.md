I found the exact root cause of the crash you experienced, and it is a fascinating and highly specific compatibility issue between **Node.js v25** and **Next.js Server-Side Rendering (SSR)**.

### 🔍 The Root Cause
You are running **Node.js v25.9.0**. Starting in Node v25, experimental native Web Storage Support (`localStorage` and `sessionStorage`) was introduced. 
* By default, Node.js v25 defines a global `localStorage` object, but it is initialized as an empty object `{}` rather than a functional storage instance (since it requires explicit flags like `--experimental-webstorage` and `--localstorage-file` to fully work).
* During server-side rendering, packages like `next-themes` (or other library dependencies) do safety checks before accessing the browser-only API, typically checking: `typeof localStorage !== 'undefined'`.
* On older Node versions, this returned `false` (meaning SSR safely skipped it). But in Node v25, it returns `true` because the global `localStorage` exists!
* The code then immediately tries to execute `localStorage.getItem(...)`. Since the object is a broken placeholder in Node 25's server-side environment, it throws the exact error you saw:
  `TypeError: localStorage.getItem is not a function`

---

### 🛠️ The Solution
I have implemented a **zero-dependency, platform-independent safeguard** at the very top of your root layout:
📄 **[src/app/layout.tsx](file:///d:/Code/my-portfolio/src/app/layout.tsx)**

```tsx
// Safeguard for Node 25+ global localStorage issue during SSR
if (typeof globalThis !== "undefined" && !globalThis.window) {
  if (globalThis.localStorage && typeof globalThis.localStorage.getItem !== "function") {
    try {
      delete (globalThis as any).localStorage;
    } catch (e) {
      try {
        globalThis.localStorage.getItem = () => null;
        globalThis.localStorage.setItem = () => {};
        globalThis.localStorage.removeItem = () => {};
        globalThis.localStorage.clear = () => {};
      } catch (err) {}
    }
  }
}
```

#### How it works:
1. It runs on the server **before** any pages or libraries compile and render.
2. It detects if `globalThis.localStorage` exists but is missing its standard API methods (like `getItem`).
3. It tries to `delete` the global object so that subsequent `typeof localStorage` checks correctly return `'undefined'` (restoring standard Node.js server behavior).
4. If the property is non-configurable, it falls back to gracefully mocking the methods to avoid throwing errors.
